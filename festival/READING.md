## 箇所1：（例：品名を追加するボタンの処理）

```swift
// 該当部分のコードを抜粋して貼る（5〜15行くらい）
let touchDistance =
    (ballStyles[first.level].diameter + ballStyles[second.level].diameter) * scale / 2
    + Game.mergeTolerance
let dx = first.position.x - second.position.x
guard abs(dx) <= touchDistance else { continue }

let dy = first.position.y - second.position.y
guard dx * dx + dy * dy <= touchDistance * touchDistance else { continue }

if first.level == second.level,
   first.level < highestLevel,
   !isEasterEgg(first.level) {
    mergeFruits(at: firstIndex, and: secondIndex)
    return
}
```

**何をしているか：**
（この部分が果たしている役割を説明する）
箱の中のボールを2つずつ、全部の組み合わせで調べて、ふれているかどうかを判定している。ふれていて、同じ種類の猫で、最強猫（cat10）より小さく、犬や「？」ボールでなければ、`mergeFruits` で1つ大きい猫に合体させる。

**なぜこう書くのか：**
（別の書き方ではなく、この書き方が選ばれている理由を説明する。分からなければ「分からない」と書いてよい）
- 2つの円がふれているかは、「中心どうしの距離 ≦ 半径の合計」で分かる。距離を出すには平方根が必要だが、両方を2乗して比べれば `sqrt` を使わなくてすむ。
- その前に `dx`（横の差）だけで先にふるい落としている。横に離れているボールは y の計算までしなくてよいので速い。この関数は1秒に60回、全部の組み合わせで呼ばれるので、軽くしておく必要がある。
- `Game.mergeTolerance`（1.5）を足しているのは、計算の誤差の余裕。物理演算で重なりを押し戻すので、ぴったり接しているボールの距離が半径の合計よりわずかに大きくなることがある。余裕がないと、となり合っているのに合体しないことがある。
- 合体したらすぐ `return` している。`mergeFruits` の中で配列 `fruits` から2つ消して1つ足すので、ループをそのまま続けると番号がずれてしまう。1フレームで合体は1回だけにして、残りは次のフレームで調べている。

**もしこう書かなかったら：**
（この部分を消したり変えたりすると何が起きるか。実際に試した結果があればここに書く）
- 変えたところ：2942行の `return` を消す
- 予想：合体した直後もループが元の個数のまま続くので、もう存在しない番号の `fruits[secondIndex]` を読もうとして「Index out of range」でアプリが落ちる。ボールが3個以上ある状態で合体が起きたときに落ちるはず（どの2つが合体したかによっては、落ちないこともある）。
- 実際に試した結果：シミュレーターで `return` を消して動かし、猫を何個か落として合体させたら、アプリが止まって動かなくなった（クラッシュした）。予想どおり、合体したあともループが続いて、配列の範囲外を読んでしまったからだと思う。

## 箇所2：（見出し）

```swift
// コードを貼る
let hasFruitOverLine = fruits.contains { fruit in
    let radius = ballRadius(fruit.level)
    let topEdge = fruit.position.y - radius
    return fruit.hasTouchedSurface && topEdge <= dangerLineY
}

if hasFruitOverLine {
    dangerClearTime = 0
    dangerElapsed += Game.tickInterval
    if dangerElapsed >= Game.dangerDuration {
        gameOver = true
        // …（タイマーを止めて、記録を保存する）
    }
} else if dangerElapsed > 0 {
    // …（ラインより上が1秒ずっと空いたら、カウントを0に戻す）
}
```

**何をしているか：**
毎フレーム、赤い点線（危険ライン）より上にはみ出しているボールがあるかを調べる。あれば `dangerElapsed` に1フレーム分（1/60秒）を足していき、合計5秒になったらゲームオーバーにして記録を保存する。ラインより上が1秒ずっと空いたら、カウントを0に戻す。

**なぜこう書くのか：**
- `hasTouchedSurface` を見ているのは、落としたばかりで落下中のボールを数えないため。持っている猫はラインより上から落とすので、これがないと落とすたびにカウントが進んでしまう。
- ボールの中心ではなく `topEdge`（中心 − 半径）で比べている。大きい猫は中心がラインより下でも、上の部分がはみ出していることがあるから。
- 一瞬ラインの下に下がっただけではリセットしない（`dangerClearTime`）。ボールがはねて上下するたびにリセットされると、いつまでも負けにならないから。
- 時間を「1/60秒ずつ足す」形で数えているので、一時停止やルーレットでこの関数が呼ばれない間は、カウントも進まない。


**もしこう書かなかったら：**
- 変えたところ：3161行の `fruit.hasTouchedSurface &&` を消す
- 予想：猫を落とすたびに、落ちていく間だけ「危険！ラインの上にボールが！」の表示が出る。1秒以内に続けて落とすとカウントがリセットされずにたまっていくので、箱がすいていても、連続で落とし続けるとゲームオーバーになることがある。
- 実際に試した結果：`fruit.hasTouchedSurface &&` を消して動かし、続けてタップして猫を落とし続けたら、箱がまだすいているのにゲームオーバーになった。落ちている途中のボールもラインの上にあると数えられて、カウントがたまってしまったからだと思う。

## 箇所3：（見出し）

```swift
// コードを貼る
func play(_ name: String) {
    stop()

    guard let player = players[name] ?? makePlayer(named: name) else { return }

    players[name] = player
    player.currentTime = 0
    player.play()
    currentPlayer = player
}
```

**何をしているか：**
猫を落としたときに、その猫の声を鳴らす。鳴らす前に、前に鳴っていた声を止めて、今の猫の声を最初から再生する。音声ファイルは猫の名前（cat1.mp3 など）で探し（`makePlayer`：71〜83行）、一度作ったプレイヤーは `players` に保存して使い回す。音量は `volumes` で音ごとに調整できる（cat5 だけ 0.5）。


**なぜこう書くのか：**
- 最初に `stop()` を呼ぶのは、同時に鳴る声を1つだけにするため。長い声もあるので、速く落とすと何重にも重なってうるさくなる。
- `players` に保存して使い回すのは、毎回ファイルを読み込むと再生が遅れるから。ゲーム開始のときに `preload` で先に読み込んでおくのも同じ理由。
- ファイルが見つからないときは、`makePlayer` の中で `print` でメッセージを出して `nil` を返す。`guard` で何もせずに抜けるので、アプリは落ちずに、どの音が足りないかが分かる。
- `shared`（1つだけのインスタンス）にしているのは、どこから呼んでも同じプレイヤーを使い、前の声を確実に止められるようにするため。
- 猫の画像も同じ名前（`ballStyles` の `name`）で Assets から読み込んでいるので、画像と音声は名前をそろえておけば追加できる。


**もしこう書かなかったら：**
- 変えたところ：55行の `stop()` を消す
- 予想：速く続けて落とすと、前の猫の声が止まらず、次の声と重なって鳴る。最強猫ができたときも cat8・cat9 の声が止まらず、cat10 の声と重なる。ただし同じ猫を続けて落としたときは、同じプレイヤーを最初から鳴らし直すので重ならない。
- 実際に試した結果：`stop()` を消して動かし、ちがう猫を速く続けて落としたら、前の猫の声が止まらずに、次の猫の声と重なって鳴った。予想どおりだった。
